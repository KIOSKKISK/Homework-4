# Теоретическая часть

**1. Парсер, считающий хеши 10 000 файлов → процессы.**
Подсчёт хеша — тяжёлые вычисления (CPU-bound), и только процессы позволяют
загрузить все ядра процессора, потому что потоки упираются в GIL.

**2. Бот, который на каждый запрос обращается к 5 внешним API → async.**
Бот почти всё время ждёт ответа от сети (I/O-bound), поэтому через async
можно отправить все 5 запросов одновременно и обслуживать много пользователей
в одном потоке.

**3. Скрипт, выгружающий 100 000 строк из БД пачками → async.**
Основное время уходит на ожидание ответа базы данных (I/O-bound), поэтому
с асинхронным драйвером (например, asyncpg) можно запрашивать следующую пачку,
пока обрабатывается предыдущая; если драйвер только синхронный — потоки.
